# Security Remediator

סקיל לתיקון פרצות אבטחה בקוד קיים. המטרה: לסגור את הממצאים **בלי לשבור מערכת חיה**. זה משלים ל-`api-security-guard` — הוא מוצא, זה מתקן.

## עיקרון-על: מדורג, לא הכל בבת אחת

מערכת production עם משתמשים אמיתיים — במיוחד multi-tenant עם נתוני לקוחות — היא סביבה שבירה. תיקון גורף של auth או בידוד דיירים בלי בדיקה יכול לנעול את כל המשתמשים בחוץ או לדלוף עוד נתונים. לכן:

1. **תקן דרג אחד בכל פעם** (הדירוג למטה). אחרי כל דרג — עצור.
2. **אחרי כל דרג הצג למשתמש**: מה שונה, אילו קבצים, ואיזו בדיקה ידנית להריץ (למשל "ודא שהלוגין עדיין עובד").
3. **אל תמשיך לדרג הבא עד שהמשתמש מאשר** שהבדיקה עברה.
4. **שמור התנהגות קיימת** — תיקון אבטחה לא אמור לשנות מה שהמשתמש רואה, רק לסגור פרצה. אם תיקון משנה API או זרימה — הדגש זאת במפורש.
5. אם קיימים טסטים — הרץ אותם אחרי כל דרג. אם אין — הצע להוסיף טסט מינימלי לנתיב הקריטי (לוגין, בידוד דייר) לפני שנוגעים בו.

## סדר הדרגים — מדליפה פעילה כלפי חוץ

תקן לפי הסדר הזה. הרעיון: קודם עוצרים דליפה שקורית עכשיו, אז דליפת נתונים, אז מנגנוני ליבה, אז הקשחה.

### דרג 0 — סוגר דליפה פעילה
נתיבים שדרכם מפתח/סוד/קובץ דולף כלפי חוץ *ברגע זה*. הכי דחוף.
- **Path traversal** שקורא קבצי שרת (.env, config) → `references/path-traversal.md`
- כל endpoint שחושף סודות ישירות.
- **אחרי סגירת דרג 0 → הזכר למשתמש לעשות rotation לכל סוד שיכל לדלוף** (מפתח API, session secret). סוד שנחשף דרך פרצה נחשב שרוף גם אחרי סגירת הפרצה.

### דרג 1 — דליפת/פגיעה בנתוני לקוחות
פרצות שחושפות או מזהמות דאטה. חשיפה משפטית אמיתית במערכת עם לקוחות.
- **Tenant isolation** — שאילתות בלי `client_id` filter → `references/tenant-isolation.md`
- **SQL injection** — קלט לא-פרמטרי, column-name injection, LIKE injection → `references/sql-injection.md`
- **אחסון סיסמאות** — plaintext, השוואה עם `==` → `references/password-storage.md`

### דרג 2 — מנגנוני ליבה (auth/session)
- session secret שנוצר מחדש בכל restart, טוקן דטרמיניסטי בלי nonce/expiry, cookie בלי secure, לוגאאוט שלא מבטל טוקן בשרת, rate limit שנעקף → `references/auth-session.md`
- זה הדרג הכי מסוכן לשבור (נועל משתמשים). הצע טסט לוגין לפני ומיד אחרי.

### דרג 3 — הקשחה ו-DoS
- שאילתות בלי LIMIT, endpoints ללא אימות (/health), validation חסר על config, מיסוך PII בלוגים, audit לפעולות רגישות → `references/hardening-dos.md`

## זרימת עבודה

1. **קבל את רשימת הממצאים.** אם המשתמש הדביק דוח (מ-api-security-guard או אחר) — מפה כל ממצא לדרג. אם אין דוח — הרץ קודם את `api-security-guard`.
2. **זהה סטאק ומבנה** — קרא את הקבצים המעורבים לפני שנוגעים. אל תתקן על סמך שם הממצא בלבד; קרא את הקוד האמיתי כדי לא לשבור לוגיקה.
3. **טפל דרג-דרג** לפי הסדר. לכל ממצא בדרג: קרא את קובץ ה-reference הרלוונטי, החל את התיקון, הסבר בעברית מה שינית ולמה.
4. **אחרי כל דרג** — סכם בטבלה (ממצא, קובץ:שורה, מה תוקן, בדיקה ידנית נדרשת), ועצור לאישור.
5. **בסוף** — צ'קליסט "לפני עלייה לאוויר" + רשימת הפעולות הידניות שנשארו למשתמש (rotation, הגדרת env בפרודקשן, הרצת migration לסיסמאות).

## כללי זהב לתיקון

- **פרמטריזציה תמיד** — אף פעם לא בונים SQL עם f-string/קונקטנציה של קלט. ערכים → placeholders. שמות עמודות/טבלאות → whitelist בלבד (אי אפשר לפרמטר שם עמודה).
- **בידוד דייר הוא not-negotiable** — כל שאילתה שנוגעת בדאטה של דייר חייבת `client_id` (או ה-scope המקביל) ב-WHERE. אם פונקציה לא מקבלת `client_id` — זו פרצה, לא נוחות.
- **constant-time להשוואות סוד** — סיסמאות/טוקנים מושווים עם `bcrypt.checkpw` / `hmac.compare_digest`, לעולם לא `==`.
- **fail closed** — בספק, חסום (403/404), אל תאפשר.
- **migration לנתונים קיימים** — תיקון אחסון סיסמאות דורש גם המרת הסיסמאות הקיימות. ספק סקריפט migration, אל תשאיר שורות ישנות שבורות.
- **אל תדפיס סודות** בצ'אט/לוג. מיקום + 6 תווים ראשונים בלבד.
- **שמור על עמודות/שמות קיימים** — אל תשנה שמות עמודות ב-DB תוך כדי תיקון; זה שובר דברים אחרים.

## הערות סטאק

- **Python/Flask** (main.py, database.py): פרמטרים עם `?` ו-tuple ל-sqlite3 / `%s` ל-psycopg. `secure_filename` + `Path.resolve()` ל-traversal. `bcrypt` לסיסמאות. session ב-server-side store (טבלה/Redis) עם `itsdangerous` או flask-session.
- **Node/Express**: prepared statements (pg/mysql2), `path.resolve` + בדיקת prefix, `bcrypt`, express-session עם store חיצוני.
- **WordPress/PHP**: `$wpdb->prepare()`, `wp_hash_password`, nonce על AJAX, `realpath()` + בדיקת prefix.
- פרטים והדגמות מלאות בקבצי ה-references.
